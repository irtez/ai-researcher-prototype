# Reviewer Agent Architecture

Архитектура улучшенного агента рецензирования с полной инструментацией, детекцией галлюцинаций и статистической оценкой качества.

## Обзор

Система состоит из пяти основных модулей, работающих в рамках Docker-контейнера academia_mcp. Каждый модуль отвечает за определенный аспект обработки статей и генерации рецензий.

**Core Review Module** (`review.py`) выполняет базовое рецензирование с инструментацией. Процесс включает проверку кэша по SHA256 хэшу PDF, парсинг текста и изображений, построение мультимодального промпта с REVIEW_PROMPT, вызов LLM через OpenRouter API со структурированным выводом через Pydantic модели. Все метрики отслеживаются в ReviewMetrics dataclass: латентность по стадиям, использование токенов, стоимость, количество попыток. Поддерживается детерминированный режим с фиксированным seed для воспроизводимости результатов.

**Batch Processing Module** (`batch_review.py`) обеспечивает массовую обработку и анализ согласованности. Функция review_with_repeats запускает несколько независимых рецензий одной статьи для расчета среднего и стандартного отклонения оценок. Ensemble_review агрегирует множественные рецензии в консенсусную с температурой 0.1 для разнообразия мнений. Review_dataset последовательно обрабатывает набор PDF файлов, сохраняя результаты в JSONL формат с продолжением работы при ошибках отдельных файлов.

**Faithfulness Module** (`faithfulness.py`) детектирует галлюцинации через верификацию утверждений рецензии против текста статьи. Извлекаются фактические утверждения по категориям (методы, эксперименты, результаты, сравнения), каждое проверяется на наличие подтверждений в тексте с цитированием конкретных разделов. Рассчитывается faithfulness_score как отношение проверенных утверждений к общему числу. Значение ниже 0.8 сигнализирует о возможных проблемах с достоверностью рецензии.

**Context Control Module** (`context_control.py`) управляет длинными статьями, превышающими лимит токенов. Стратегия truncation отсекает текст по секциям с сохранением начала (abstract, introduction) или конца (methods, results). Стратегия summarization использует LLM для сжатия до 5k токенов с сохранением ключевой информации. Гибридный подход комбинирует оба метода для баланса скорости и качества. Бюджетирование резервирует 10k токенов для изображений из общего лимита 50k.

**Evaluation Pipeline Module** (`eval_pipeline.py`) рассчитывает статистические метрики качества рецензента при наличии ground truth оценок. MAE и RMSE измеряют абсолютную точность предсказаний. Spearman correlation оценивает качество ранжирования статей, Pearson correlation — линейную связь оценок. Consistency metrics анализируют стабильность через дисперсию повторных рецензий. Результаты сериализуются в JSON для отслеживания во времени и сравнения конфигураций.

## Расширенная архитектура (Tier 1 + Tier 2)

Добавлены пять новых модулей для повышения точности, глубины анализа и снижения галлюцинаций.

**Section Parser Module** (`section_parser.py`) реализует структурированное извлечение секций из PDF (Tier 1, Item 1). Вместо обработки текста как единой простыни, модуль автоматически распознает именованные секции: Abstract, Introduction, Related Work, Methods, Experiments, Discussion, Conclusion, References. Используются regex паттерны для типичных заголовков ML/CS статей и анализ формата (размер шрифта, жирность). Выигрыш: LLM работает значительно точнее при наличии контекста секции ("это из Methods" vs просто текст). References секция автоматически исключается из основного промпта, экономя 15-25% токенов (~3-5k на статью). ParsedPaper dataclass предоставляет удобные доступы к abstract, methods, experiments через атрибуты.

**Extended Models Module** (`models.py`) заменяет 4 базовых критерия на 7 детализированных (Tier 1, Item 2). Новые критерия: Originality, Importance (важность исследовательского вопроса), Claim Support (обоснованность утверждений), Experimental Soundness (корректность экспериментов), Clarity, Community Value (ценность для сообщества), Contextualization (позиционирование относительно prior work). Итоговый overall score вычисляется не через прямой предикт LLM ("число из воздуха"), а через взвешенную регрессию: weighted_average = sum(score_i * weight_i). Веса откалиброваны на основе PeerRead датасета: originality=0.20, claim_support=0.18, experimental_soundness=0.17, importance=0.15, community_value=0.12, clarity=0.10, contextualization=0.08. Такой подход резко улучшает Spearman correlation за счет сглаживания шума LLM через агрегацию стабильных компонентов. Функция map_to_overall_score преобразует взвешенный score (1-4 scale) в итоговый overall (1-6 scale) через пороговые значения.

**arXiv Search Module** (`arxiv_search.py`) выполняет targeted поиск похожих работ для оценки новизны (Tier 1, Item 3). Извлекает ключевые термины из Abstract + Methods + Introduction через частотный анализ и паттерны (капитализированные термины, акронимы, технические существительные). Ищет на arXiv через Academia MCP tools с фильтром по дате (последние 3 года). Рассчитывает similarity score через Jaccard similarity на множествах ключевых слов. Формирует контекстный блок "Related Recent Work" с top-3 наиболее похожими статьями (title, abstract, arxiv_id, year, similarity). Этот блок добавляется в промпт отдельной секцией для оценки Originality и Contextualization. Закрывает главную слабость LLM-ревьюеров — незнание свежих работ после cutoff даты обучения.

*Техническая реализация интеграции с Academia MCP:*
- Импортирует синхронную функцию `arxiv_search` из пакета `academia_mcp.tools`.
- Чтобы сетевые запросы к API arXiv не блокировали асинхронный Event Loop, вызовы выполняются в фоновом пуле потоков через `asyncio.to_thread`.
- Полученные результаты приводятся к типу структурированного ответа `ArxivSearchResponse`, откуда извлекаются поля объектов `ArxivSearchEntry` (`title`, `abstract`, `id`, `published`).

**A3PR Pipeline Module** (`a3pr_pipeline.py`) реализует 4-ступенчатый каскадный reasoning вместо одного гигантского промпта (Tier 2, Item 4). Каждый вызов решает одну задачу, снижая когнитивную нагрузку на модель:
- **Stage 1 (Analysis)**: Извлечение фактов — goals, methods, datasets, claims, limitations, key_contributions. Выход: AnalysisResult JSON с обязательными citation к секциям/страницам.
- **Stage 2 (Argument)**: Формулировка аргументов за/против принятия. Вход: AnalysisResult + related work контекст. Выход: ArgumentResult с pros[], cons[], open_questions[]. Каждый аргумент требует evidence citation из AnalysisResult.
- **Stage 3 (Assessment)**: Оценка по 7 критериям с обоснованием. Вход: AnalysisResult + ArgumentResult. Выход: AssessmentResult с scores + reasoning per criterion.
- **Stage 4 (Polish)**: Сборка финального ревью программно. Вычисляет weighted overall score, компилирует reasoning из assessment, формирует ExtendedReviewResponse.
Затраты: 4 вызова вместо 1, суммарный рост токенов ~30-40%. Выигрыш: непропорционально более высокое качество за счет специализации вызовов и явных ссылок на фрагменты статьи (ключевое требование для снижения hallucinations).

**Self-Critique Module** (`self_critique.py`) добавляет loop проверки качества ревью (Tier 2, Item 5). После финального ревью отдельный LLM вызов проверяет по чек-листу: (1) Score-Reasoning Alignment — соответствуют ли оценки тексту (score 3 с позитивным текстом = inconsistency), (2) Section Coverage — охвачены ли Methods, Experiments, Related Work, Limitations, (3) Evidence Citations — есть ли конкретные ссылки на секции/страницы для каждого утверждения, (4) Novelty Assessment — подкреплена ли оценка новизны сравнением с prior work, (5) Question Quality — являются ли вопросы к авторам отвечаемыми (не риторическими). CritiqueResult содержит issues_found[], corrections_made[], consistency_score (0-1), completeness_score (0-1). При наличии revised_review применяется автоматическая коррекция. Loop выполняется до 2 итераций или достижения consistency_threshold >= 0.8. Ловит типичные ошибки: score 2 с позитивным обоснованием, weaknesses без снижения quality score, отсутствие цитат.

## Интеграция

Модули подключаются через volume mounts в docker-compose.yml, что позволяет обновлять код без пересборки образа. Требуется точное совпадение путей импорта и отсутствие циклических зависимостей. Конфигурация через переменные окружения OPENROUTER_API_KEY, BASE_URL, REVIEW_MODEL_NAME.

Наблюдаемость обеспечивается Langfuse для трассировки LLM вызовов и локальным логированием с уровнями INFO, WARNING, ERROR, DEBUG. Кэширование in-memory с потерей при перезапуске контейнера. Обработка ошибок через retry логику до 3 попыток и graceful degradation для продолжения работы пайплайна при частичных сбоях.

Новые модули интегрированы в review_pdf_paper через флаги: use_sections (Section Parser), use_a3pr (A3PR Pipeline), use_self_critique (Self-Critique), use_arxiv_search (arXiv Search). По умолчанию use_sections=True, остальные False для обратной совместимости.

## Производительность

Одна рецензия занимает 50-70 секунд: парсинг PDF с, рендеринг изображений 2с, валидация <1с. Кэширование сокращает повторные вызовы до <1с. Отключение изображений экономит 2-5с. Контекстный контроль добавляет 5-10с на суммаризацию.
