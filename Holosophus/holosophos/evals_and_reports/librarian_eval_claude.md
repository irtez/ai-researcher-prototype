# Librarian Eval (Claude Code mode)

Evaluates the librarian agent's ability to find specific ArXiv papers by their ID given a natural language query.

## How to run

### Librarian eval (15 questions)

Ask the manager (Claude Code) to run librarian eval as 2 parallel sub-agents:

```
Run librarian eval. Launch 2 librarian sub-agents in parallel:
- Sub-agent 1: answer questions from evals_and_reports/data/librarian_test.jsonl (9 questions)
- Sub-agent 2: answer questions from evals_and_reports/data/librarian_additional_test.jsonl (6 questions)

For each question, find the exact ArXiv paper ID.
Save results to workdir/eval_librarian_core/results.md and workdir/eval_librarian_additional/results.md
Format: Q1: <arxiv_id>\nQ2: <arxiv_id>\n...

Monitor progress by checking if result files exist. When both are done, score against targets.
```

### GAIA eval (30 questions, 6 parallel agents)

```bash
python scripts/run_gaia_eval.py \
    --data holosophos/evals_and_reports/data/gaia_eval_30_stratified.json \
    --max-parallel 6
```

**Parallelism:** `--max-parallel N` controls how many Agent SDK sessions run concurrently. Each session is a full manager→librarian/mle-solver pipeline. Default: 6.

**Monitor:**
```bash
cat workdir/eval_gaia_*/progress.txt             # X/30 completed
ls workdir/eval_gaia_*/q*/result.json | wc -l    # count finished
cat workdir/eval_gaia_*/report.md                 # final report (after completion)
```

**Results directory:** `workdir/eval_gaia_<timestamp>/`
- `q{idx}/result.json` — per-question result with answer, trajectory, token usage
- `progress.txt` — live progress counter
- `report.md` — final scored report
- `results.jsonl` — machine-readable results

## Datasets

| File | Questions | Schema |
|------|-----------|--------|
| `data/librarian_test.jsonl` | 9 | `{"query": "...", "target": ["arxiv_id"]}` |
| `data/librarian_additional_test.jsonl` | 6 | `{"query": "...", "target": ["id1", "id2", ...]}` |
| `data/gaia_eval_30_stratified.json` | 30 (L1=10, L2=16, L3=4) | `{"question": "...", "answer": "...", "level": N}` |

## Results

### 2026-03-28 — Librarian baseline (Claude Code, no AlphaXiv)

**Config:** Claude Opus 4.6, MCP tools: academia + mle_kit, no AlphaXiv, maxTurns=100

| Set | Accuracy | Duration | Turns | Tool calls | Output tokens | Cache rate |
|-----|----------|----------|-------|------------|---------------|------------|
| Core (9q) | 7/9 = 78% | 51 min | 800 | 85 | 12,838 | 99% |
| Additional (6q) | 5/6 = 83% | 51 min | 772 | 73 | 17,843 | 100% |
| **Total** | **12/15 = 80%** | **~51 min** | **1,572** | **158** | **30,681** | **99%** |

**Failures:**
- Q5 core: "self-speculative decoding with early exit" → found 2404.16710 instead of 2309.08168
- Q9 core: "benchmarking role-playing LMs" → missed 2409.06820
- Q6 additional: "LLM agents for financial tasks" → found 2412.18174 instead of 2409.14913

### Metrics glossary

- **Turns** — LLM reasoning steps. High count = agent explored many search queries.
- **Tool calls** — total MCP tool invocations.
- **Output tokens** — tokens generated by the agent.
- **Cache rate** — % of input tokens served from Claude's prompt cache. 99% = efficient context reuse.
