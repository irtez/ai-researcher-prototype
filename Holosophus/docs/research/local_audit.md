## Existing compactor implementations

The prior **compaction_policies__20260508_0231** session implemented **five distinct compaction strategies** in `workdir/compaction_policies__20260508_0231/mle/code/compactors.py`:

1. **`full_context`** (passthrough, ~line 39–56)
   - Input: list of Segments + live query + budget + LLM client
   - Output: All segments verbatim, audit notes it's a no-op
   - Use case: baseline, no compression
   - Token preservation: 100%

2. **`naive_truncation`** (recency bias, ~line 62–102)
   - Keeps all system messages + last-N turns within budget, walking backward from recent
   - Inserts truncation marker with dropped-turn count
   - Simple and deterministic, no LLM calls
   - Audit captures: dropped turns, kept turns, budget used
   - **Token preservation:** variable (budget-constrained)

3. **`rolling_summary`** (task-agnostic chunk summarization, ~line 108–176)
   - Splits history into fixed-size chunks (default W=20 turns)
   - Keeps last K chunks verbatim (default K=2)
   - Summarizes older chunks via LLM with `<=200 word` prompt
   - Summary segments tagged with chunk metadata (src_turns, chunk_idx)
   - Uses `_render_chunk()` helper to format segment history as `[sid tN role] content`
   - **Token preservation:** ~30–50% depending on chunk size and summary efficiency

4. **`type_aware`** (per-role budget allocation with fallback policies, ~line 202–431)
   - **Most sophisticated strategy**
   - Assigns budget shares by segment role (system 5%, user 45%, assistant_text 35%, tool 5% each)
   - Per-role compression:
     - **system**: always verbatim
     - **user**: if overflow, keeps recent verbatim up to 60% budget cap; older user turns compressed to 1-line summaries with LLM ("Compress each line into a 1-line bullet…")
     - **assistant_text**: rolling summary over chunks (same as rolling_summary) if can't fit verbatim
     - **tool_call** / **assistant_reasoning**: keep last 3 verbatim, rest become stubs with `[role stub: tool=X arg_keys=[...]]`
     - **tool_result**: keep last 3 verbatim, rest get head-200 + tail-200 extract + LLM 20-word summary
   - Slack rolls forward: unused share from one type available to next
   - Final segments re-sorted by (session_idx, turn_idx)
   - **Token preservation:** 20–40% (aggressive compression on most types)

5. **`task_aware`** (single unified LLM call with live query context, ~line 435–509)
   - Renders entire history in `[session-N, turn-T, role-X] content` format
   - Single LLM prompt: "Reduce to <=N tokens, keep verbatim what's relevant to: {live_query}"
   - Optional: can enable Gemini-3-Flash thinking budget via `extra["reasoning"]`
   - Output: single assistant_text Segment with `[compacted history (task-aware), original=Xt]` prefix
   - **Audit captures:** compactor prompt/completion tokens, budget, thinking flag, text preview
   - **Token preservation:** 15–30% (maximum compression, relies on LLM relevance judgment)

**Common patterns across all:**
- All take `(history: list[Segment], live_query: str, budget: int, llm, *, experiment: str, item_id: str, compactor_model: str, **strategy_kwargs)`
- All return `CompactedHistory(segments, original_tokens, compacted_tokens, strategy, audit: dict)`
- Tokenization: uses `tiktoken.cl100k_base` (OpenAI's standard encoder)
- Segment metadata carries session_id, turn_idx, date, has_answer for audit trail

## API contract between compactor and caller

**Function signature (all five strategies follow this):**
```python
async def compact_<strategy>(
    history: list[Segment],              # Prior conversation (excludes live query)
    live_query: str,                     # The user's current/upcoming question
    budget: int,                         # Token target for output
    llm,                                 # LLMClient instance (has .complete() method)
    *,
    experiment: str,                     # For cost/trace logging
    item_id: str,                        # For audit trail
    compactor_model: str,                # Which model to use for summarization (if needed)
    **strategy_kwargs                    # Strategy-specific knobs (chunk_size, keep_last_chunks, etc.)
) -> CompactedHistory:
```

**CompactedHistory return:**
```python
@dataclass
class CompactedHistory:
    segments: list[Segment]              # New (compacted) message list
    original_tokens: int                 # Token count of input history
    compacted_tokens: int                # Token count of output segments
    strategy: str                        # Strategy name (e.g., "rolling_summary")
    audit: dict = field(default_factory=dict)  # Strategy-specific metrics/decisions
```

**Registry pattern** (~line 514–520):
```python
STRATEGIES: dict[str, Callable[..., Awaitable[CompactedHistory]]] = {
    "full_context": compact_full_context,
    "naive_truncation": compact_naive_truncation,
    # ... etc
}
```

**Key observations:**
- **Not budget-aware in a hard sense:** budget is advisory; task_aware respects it; naive_truncation respects it; rolling_summary ignores it (uses fixed chunk size)
- **Live query is passed but not always used:** only task_aware reads it; others ignore it
- **Async throughout:** all compactors are `async def`, calls to LLM via `await llm.complete()`
- **Stateless:** no side effects, pure functional — same history + budget → same output

## Conflicts / things to NOT reuse

1. **LongMemEval-specific assumptions:**
   - The prior session assumes each Segment is one utterance (turn) from LongMemEval's `(user, assistant)` pairs
   - New framework may have multi-turn tool sequences; the segment granularity will differ
   - **Don't copy** the flattening logic (`flatten_longmemeval_history`) wholesale; build a new one for your frame

2. **Chunk size heuristics as fixed constants:**
   - `rolling_summary` defaults to W=20 turns per chunk, K=2 tail chunks
   - These were tuned for LongMemEval's needle-in-haystack task
   - For new framework, these should be **configurable or learned**, not hardcoded

3. **LLM summarization prompts baked into compactors:**
   - Prompts like `"Summarize in <=200 words…"` are in the function bodies
   - New framework should externalize prompts (config/strategy overrides), not hardcode
   - **Current architecture:** prompts ∈ code; desired: prompts ∈ config

4. **Type-aware TYPE_SHARES hardcoded:**
   ```python
   TYPE_SHARES: dict[str, float] = {
       "system": 0.05,
       "user": 0.45,
       "assistant_text": 0.35,
       ...
   }
   ```
   - Works for LongMemEval (mainly user + assistant)
   - Tool-heavy frameworks (tau-bench) need different splits (tool_call + tool_result prominence)
   - **Design debt:** should be a per-strategy param, not module-level constant

5. **Blocking assumption on single LLM model:**
   - All compactors assume `llm.complete(model=compactor_model, ...)`
   - Doesn't consider multi-model pipelines (cheap ranker → expensive summarizer)
   - New framework should support model selection per step

6. **No online / streaming compaction:**
   - All strategies work on full history snapshot
   - No support for "summarize as we go" patterns
   - Acceptable for now, but note for future versions
