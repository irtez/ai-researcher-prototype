# Локальный запуск Claude Code с веб-интерфейсом

Конфигурация `docker-compose.claude.yml` запускает UI, API файлов сессий,
четыре локальных MCP, Langfuse v3 и Phoenix. Runner и авторизованный Claude
Code CLI работают на хосте. Химический профиль с дополнительными MCP описан
в [отдельной инструкции](chemistry-local.md).
Настройки обоих профилей для подтверждения этапов и повторных доработок —
в [инструкции по согласованиям и замечаниям](approvals-and-feedback.md).
Встроенный Bash исследовательских агентов исполняет команды в контейнере
сессии; окружение, пути и остановка описаны в [инструкции Docker Bash](docker-bash.md).

Настройка модели и выбора effort: [модельные подключения](model-connections.md).

## Подготовка

Исходные настройки CLI и MCP обоих профилей находятся в
`config/claude-code.yaml`. Runner и CLI launcher читают этот YAML напрямую.
Химические адреса можно переопределить через `CHEM_MCP_URL` и
`CHEM_CONVERSIONS_MCP_URL`; авторизация подставляется при запуске.
Секреты остаются в окружении и не записываются в YAML или Git.

`.mcp.json` — производный файл общих серверов для штатного CLI и прежних
вспомогательных скриптов. После изменения YAML обновить его командой
`uv run python scripts/cc_config.py --write-compat`; `make verify` проверяет
согласованность. Производный файл содержит значения по умолчанию, без
раскрытия env и OAuth-заголовков.

`cli_env` включает проверку сертификатов (`NODE_TLS_REJECT_UNAUTHORIZED: "1"`)
для исследовательских запусков, помощника названия и внутренних критиков.
Это перекрывает случайно унаследованное отключение проверки в дочернем CLI.
Настройки прокси и доверенных CA продолжают наследоваться; глобальное
окружение пользователя не меняется.

Все команды выполняются из `Holosophus/`. Требуются Docker с Compose 2.24.4+
(поддержка `!override`), uv, Python 3.12+ и Claude Code CLI.

```bash
cp .env_example .env  # только если собственного .env ещё нет
uv sync --locked
claude auth status
```

Для чтения PDF встроенным `Read` нужны `pdftoppm` и `pdfinfo` в PATH
пользователя, который запускает runner. В Debian/Ubuntu их предоставляет
пакет `poppler-utils` (`sudo apt-get install poppler-utils`). Проверьте
`pdftoppm -v` и `pdfinfo -v` в окружении runner, включая PATH службы systemd.
При установке без административных прав можно использовать отдельный
пользовательский каталог с утилитами и их зависимостями. Установка только
в контейнер Academia или Bash не обеспечивает работу хостового `Read`.
Для преобразования PDF внутри Bash эти утилиты должны быть в его образе
либо установлены в окружении сессии. Подготовленный образ из `.env_example`
собирается один раз командой `make executor-image`. Его состав и порядок
обновления описаны в [инструкции Docker Bash](docker-bash.md).
MCP `compile_latex` использует свой
готовый контейнер и не требует установки LaTeX на хост.

Если CLI уже авторизован через подписку, оставьте `CLAUDE_CODE_OAUTH_TOKEN`
и `ANTHROPIC_API_KEY` пустыми. При необходимости авторизуйтесь в отдельном
терминале. Ключи отдельных MCP (`OPENROUTER_API_KEY`, `TAVILY_API_KEY` и другие)
задаются в `.env` по используемым инструментам. Для старта runner ключ
OpenRouter не требуется: авторизация основной модели проверяется по выбранной
записи `config/models.yaml`, а MCP-сервисы используют собственные настройки.

До первого запуска Langfuse задайте собственные `LANGFUSE_PUBLIC_KEY_V3`,
`LANGFUSE_SECRET_KEY_V3`, `LANGFUSE_INIT_USER_PASSWORD`,
`LANGFUSE_INIT_USER_EMAIL` и `LANGFUSE_INIT_USER_NAME`. При пустой БД сервис
создаст пользователя и проект из этих значений. Адрес API для host runner —
`LANGFUSE_BASE_URL_V3=http://localhost:3051`. Файл `.env` не коммитится.

Экспорт трасс Claude Code в Phoenix включается через `ENABLE_PHOENIX=true`.
Для локального коллектора задайте
`PHOENIX_ENDPOINT=http://127.0.0.1:6007/v1/traces` и
`PHOENIX_PROJECT_NAME=ai-researcher`. Порт публикации задаёт
`PHOENIX_CC_UI_PORT=6007`; при его изменении обновите и endpoint. Значение
`ENABLE_PHOENIX=false` отключает экспорт, сохраняя Langfuse. После изменения
настроек перезапустите runner. Сервис Phoenix запускается независимо от
этого флага; доставка трасс в него не является условием работы runner.

Для локальных вычислений без GPU оставьте `LOCAL_GPU_DEVICES` пустым.
Для доступа к локальной видеокарте укажите её индекс после проверки
GPU в Docker по [инструкции исполнителя](docker-bash.md).
Например, `LOCAL_GPU_DEVICES=0` открывает новым сессиям устройство 0.
Режим «Локально» в UI означает место исполнения и допускает как CPU,
так и настроенный GPU. Если внешнего
SSH-ключа нет, задайте `CLOUDRU_SSH_KEY_HOST_PATH=/dev/null` и
`SELECTEL_SSH_KEY_HOST_PATH=/dev/null`. Не задавайте пустую строку для
`EXISTING_INSTANCE_ID`: необязательный числовой параметр следует пропустить.

## Запуск

```bash
make up-claude
make cc-runner  # отдельный терминал; оставить работающим
```

`make up-claude` ждёт готовности сервисов, включая HTTP health Langfuse.
Runner запускайте после успешного завершения этой команды: он проверяет
телеметрию при старте и сохраняет результат проверки в процессе.

### После перезагрузки ПК

Запуск Docker сам по себе не восстанавливает весь стенд: у UI и MCP сейчас
нет политики автоматического перезапуска, а host runner работает отдельным
процессом вне Docker. После запуска Docker восстановите уже собранный стек:

```bash
cd /home/irtez/notebooks/diplom/ai_scientists-chemistry/Holosophus
docker compose -f docker-compose.claude.yml --profile chemistry up -d --wait
make cc-runner  # оставить терминал открытым
```

Пересборка для обычного перезапуска не нужна. Эти команды не запускают
исследовательскую задачу и не обращаются к модели; задача отправляется из UI.

### Адреса сервисов

Откройте UI: `http://localhost:5062`. В форме по умолчанию выбран Claude Code;
для первого локального прогона выберите вычислительный режим `Local`.
Langfuse доступен на `http://localhost:3051`; данные входа находятся в `.env`.
Phoenix доступен на `http://127.0.0.1:6007`; тот же порт принимает OTLP/HTTP
на `/v1/traces`, отдельный порт gRPC не используется.

Compose использует отдельный проект `ai-researcher-claude` и собственные
volumes. Старый сервер CodeArkt, Langfuse v2 и прежний Phoenix в этот запуск
не входят. Исходные конфигурации остаются доступны для прежнего способа
развёртывания. Переключение UI на CodeArkt требует отдельно запущенного
старого backend.

Phoenix хранит данные в `/mnt/data` внутри контейнера: каталог подключён к
тому `ai-researcher-claude_phoenix_data`, который сохраняется при обычном
`make down-claude`. Прежний Phoenix на порту 6006 использует своё хранилище.

`workdir/` разделяется runner, UI API и MCP. MCP-порты 5056, 5057, 5059 и 5060
соответствуют `.mcp.json`. UI и опубликованные Docker-сервисы слушают loopback.
Host runner слушает `0.0.0.0:5061`, чтобы к нему мог обратиться контейнер UI
через `host.docker.internal`. Это конфигурация локального стенда.

При сборке промптов обоих профилей пути к исходным навыкам writer преобразуются
в абсолютные пути рабочей копии. Записи реестра, начинающиеся с
`holosophos/holosophos/skills/`, разрешаются относительно явно указанного корня
исходного проекта; остальные — относительно самого реестра. Файлы навыков
читаются на месте, результаты сохраняются в каталоге сессии.

## Проверка без модели

```bash
docker compose -f docker-compose.claude.yml config --quiet
docker compose -f docker-compose.claude.yml ps
curl --fail http://localhost:5061/health
curl --fail http://localhost:5062/ui/health
curl --fail http://localhost:3051/api/public/health
curl --fail --output /dev/null http://127.0.0.1:6007/
```

Эти команды проверяют инфраструктуру. Они не запускают исследование,
не арендуют ВМ и не подтверждают поведение агентов. Проверку с LLM и её
сценарий согласовать отдельно; наличие авторизации само по себе не является
разрешением на такой запуск.

Остановка: завершите `make cc-runner` через Ctrl+C и выполните
`make down-claude`. Volumes и файлы исследований сохраняются.

## Минимальная проверка с моделью

Текущий смоук выполняется через UI штатным процессом, после отдельного
согласования сценария. Можно повторить короткое сравнение молекулярных масс
этанола и уксусной кислоты с одной делегацией экспериментатору, затем
проверить доработку округления в той же сессии. Это проверяет новую среду
исполнения вместе с согласованиями, результатом и интерфейсом.

Прежний `scripts/smoke_test_cc_local.py` оставлен как исторический ограниченный
эксперимент с MCP Bash. Он не является проверкой текущего Docker Bash и не
используется для штатного смоука. Технические проверки без модели описаны
в [Docker Bash](docker-bash.md).

### Вложения при выборе CodeArkt

Форма загрузки исходных файлов доступна для обоих вариантов среды выполнения.
Переключение среды сохраняет выбранные файлы. Общий UI API сохраняет их в
`inputs/` сессии, затем сервер CodeArkt проверяет владельца и пути и передаёт
их менеджеру. После начала работы первоначальные вложения не перезаписываются.
Подключение этого обработчика задаётся сборкой менеджера AI Researcher.
Запуск без вложений сохраняет прежний контракт CodeArkt. Для использования
CodeArkt нужен отдельно запущенный сервер этой среды, как указано выше.

Новые вложения при доработке, согласования и управление исследовательской
беседой остаются в реализации Claude Code. Поддержка первоначальных вложений
не переносит эти механизмы в CodeArkt.
