# Сводки экспериментатора

Общий контракт Claude Code для general и chemistry, локального и удалённого
экспериментатора. Он заменяет обязательное ручное заполнение `mle/log.jsonl`.

## Содержание и запись

К завершению поручения экспериментатор сохраняет краткое объяснение смысловых
этапов: что сделано, что получилось, какие ограничения или неудачи обнаружены.
Поле `summary` содержит короткий Markdown: обычно 2–4 пункта по предложению
о действии, основном результате и существенном ограничении. Для небольшой
поправки достаточно нескольких строк об изменении. Разные содержательные
этапы оформляются отдельными элементами массива. Полные числовые таблицы,
погрешности представления float, имена функций, хеши и подробности окружения
остаются в рабочих файлах. Указывать их в сводке нужно только для объяснения
запрошенного результата или реальной ошибки.

Обычные чтения и записи файлов не требуют отдельных пунктов. Это пояснение
модели; техническая лента вызовов и статусы продолжают формироваться системой.

Система создаёт `mle/summaries/<iteration>/` и передаёт менеджеру
`EXPERIMENT_SUMMARY_DIRECTORY` в контексте текущей итерации. Менеджер выбирает
новое описательное имя JSON для каждого нового поручения и передаёт полный
относительный путь специалисту в поручении. Метка `EXPERIMENT_SUMMARY_PATH`
необязательна: это путь файла, а не переменная окружения или второй документ. Техническое
продолжение того же поручения использует прежний путь. Предыдущие сводки
сохраняются; новая доработка получает новый каталог.

Формат файла — JSON-массив:

```json
[
  {
    "phase": "Построение калибровки",
    "summary": "- **Метод:** построена линейная калибровка.\n- **Результат:** рассчитаны концентрации двух образцов.",
    "artifacts": ["mle/code/calibration.py", "mle/results/calibration.json"]
  }
]
```

Пути артефактов отсчитываются от корня сессии. Время, номер строки, статус и
дублирующий объект метрик не нужны. Язык соответствует запросу пользователя.
Сохранения перед итоговым ответом достаточно; отдельный модельный запрос для
сводки не создаётся. Отсутствие сводки не блокирует публикацию основного результата.

Менеджер получает ответ экспериментатора и ссылки на результаты. Обязательного
перечитывания или переписывания сводки нет. Если специалисту не передали путь,
он возвращает сводку в своём ответе, не угадывая каталог другой итерации.
Путь, переданный обычной фразой, достаточен; искать специальную переменную
в окружении или исходном пользовательском запросе не требуется.

Формат сводки задан в `mle_solver.yaml → claude_code.artifact_prompt` и напрямую
подключается к local/remote MLE обоих профилей. Менеджер назначает путь, но
не пересказывает и не расширяет схему. Каталоги кода и результатов определяет
экспериментатор по своему контракту; менеджер не назначает альтернативную структуру.
Выводы, неудачи и ограничения включаются
в текст `summary`; отдельные поля `findings`/`limitations` не предусмотрены.
Общий блок `prompts/shared/claude_code.yaml` задаёт русский язык пользовательских
артефактов и видимых сообщений по умолчанию. Английское поручение не меняет язык сводки.

CodeArkt собирает `canon + codearkt` с собственным CodeAct-шаблоном. Инструкции
новой сводки и каталогов итераций в него не добавляются; его прежний `mle/log.jsonl`
сохранён в `codearkt.system_extras`. Проверка сборки текста не является проверкой
выполнения CodeArkt.

## UI и совместимость

API возвращает `experiments.summaries` отдельно от таблиц метрик. Итерация
определяется по каталогу, а не по полю, написанному моделью. Вкладка
«Эксперименты» показывает блоки по итерациям: название этапа, полный текст,
ссылки на найденные артефакты. Поле `summary` проходит через тот же Markdown-рендерер,
что и сообщения: абзацы, списки, выделения и код отображаются с форматированием.
Markdown-ссылки отсчитываются от файла сводки; ссылки массива `artifacts` — от
корня сессии. Ширина карточки ограничена 960 px; текст переносится, многоточие
и ограничение высоты не применяются. Путь отсутствующего артефакта остаётся
обычным текстом. Старые сводки читаются без миграции, но длинный абзац без
разметки сам по себе не превращается в краткий список. Сохранённые файлы
автоматически не переписываются и дополнительные LLM-вызовы не добавляются.

Некорректная сводка показывается с ошибкой и ссылкой на исходник.
Вкладка доступна и при наличии только сводки, без кода и таблиц результатов.
Общий предел чтения JSON — 512 000 байт: превышение вызывает явную ошибку вместо скрытого
обрезания текста. Старый журнал сохраняется как файл и в сворачиваемом архивном
разделе; прежние метрики не мигрируют и не пересчитываются.

Resume использует сохранённую беседу SDK и реально записанные результаты и
контрольные точки. Сводка не является механизмом восстановления и может
отсутствовать при аварийном завершении. Старые опциональные сценарии
`scripts/test_mle_artifacts.py` и `scripts/test_mle_recovery.py` проверяли прежний
ручной журнал; они не являются проверкой этого контракта.

## Проверки без LLM

`tests/test_experiment_summaries.py` проверяет каталоги итераций, сохранение
полного текста, несколько поручений, архив и ошибки чтения.
`tests/test_cc_runner_profiles.py` и `tests/test_result_contract.py` проверяют
контекст рабочих путей в настоящей сборке SDK-опций UI/CLI.
`ui/tests/iteration-history-browser.py` использует реальный API с синтетическими
файлами: сводки двух итераций, Markdown-списки и абзацы, выделение, inline-код,
ссылки на файлы, перенос длинного текста, мобильная ширина и открытие
артефактов. Реальная LLM в этих проверках не вызывается.
