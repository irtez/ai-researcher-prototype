# Локальный запуск химических MCP

Химический профиль использует два отдельных MCP-сервиса: `chem` для таблиц,
структур, PubChem, ChemX и ADME; `chem_conversions` для преобразования химических
представлений. Они входят в Compose profile `chemistry`, поэтому обычный
`make up-claude` их не запускает.

## Запуск и остановка

Команды выполняются из `Holosophus/`:

```bash
make up-chemistry
make chemistry-tools-list
```

Сервис `chem` публикуется только на loopback по адресу
`http://127.0.0.1:5063/mcp`, а `chem_conversions` —
`http://127.0.0.1:5064/mcp`. Остановка сохраняет workspace и Docker-кеши:

```bash
make down-chemistry
```

Первичная сборка `chem` устанавливает ADMET-AI и его зависимости. Модель ADMET
создаётся только при первом вызове NN-инструмента. Наборы ChemX загружаются
при первом запросе и сохраняются вне слоя контейнера; старт MCP их не загружает.
Два выбранных набора можно подготовить заранее командой
`make chemistry-prepare-datasets`. Реестр, локальные версии и подключение
источников описаны в [инструкции по наборам](chemistry-datasets.md).

## Файлы сессии

В UI (`http://127.0.0.1:5062`) выберите «Химия» перед новой задачей. В опциях
будут выбраны Claude Code и Local. Модель выбирается отдельно: по умолчанию
Opus, также доступны Sonnet и Haiku. Перечень, подключения и effort задаются
в [реестре моделей](model-connections.md). Профиль сохраняется при старте; продолжение
использует тот же профиль. Для другой задачи создайте новую сессию.

До запуска можно прикрепить несколько CSV, XLS, XLSX, DOCX, JSON, JSONL, PNG,
JPG/JPEG или PDF. Загрузка доступна в обоих профилях Claude Code — «Общий»
и «Химия»; переключение профиля сохраняет выбранные файлы. Максимум —
20 МиБ на файл; nginx ограничивает весь запрос
256 МиБ. Существующие файлы не перезаписываются. Оригиналы попадают в `inputs/`, а их пути — в задачу
менеджера. Изображения читаются встроенным Read либо подходящим инструментом.
После завершения итерации новые файлы можно прикрепить к замечанию через форму
доработки. Они сохраняются отдельными версиями, не заменяя прежние входы;
при включённой галочке источников потребуется новое согласование.
[Подробности](research-iterations.md#вложения-при-доработке).

Химические инструкции собираются из общих YAML и переопределений
`prompts/profiles/chemistry/` отдельно для каждой сессии. Сохраняются manager и
в режиме Local пять ролей, включая локального экспериментатора. Удалённая MLE-роль и
remote-инструменты в этом режиме отключены также для manager; native Bash и локальный
LLM-прокси сохранены. Native Bash использует общий для обоих профилей
[контейнерный исполнитель](docker-bash.md).
Writer использует прежний LaTeX/PDF-процесс, химические навыки и проверки без
минимума восьми страниц. Общий профиль сохраняет прежний порог.

В химическом UI/CLI-запуске `setting_sources=[]` отключает неявную загрузку
пользовательских и проектных настроек, включая их hooks и файлы агентов.
Иначе общие `.claude/agents/*.md` могут перекрыть переданные химические роли.
Промпты, роли, MCP и hooks передаются приложением явно; native tools и
файлы навыков по путям в промптах остаются доступны. Настройки химического
стенда по-прежнему читаются приложением из `.env`. Общий профиль не меняется.

CLI использует тот же профиль, например:

```bash
uv run --locked python scripts/run_research.py --research-profile chemistry --dump-prompts
```

Эта команда только печатает инструкции. Фактический запуск принимает также
`--model sonnet`; `--resume --workdir workdir/<session_id>` восстанавливает
профиль и сохранённую модель. Для chemistry каталог сессии должен находиться
в общем workspace, смонтированном в MCP-контейнеры. Прямой CLI-запуск с задачей
обращается к модели.

Контейнер `chem` использует общий host-каталог `workdir/` как `/workdir`.
UI API создаёт входные файлы от UID/GID host runner (по умолчанию 1000:1000).
Если пользователь запуска имеет другие значения, задайте `AI_RESEARCHER_UID`
и `AI_RESEARCHER_GID` в локальной конфигурации Compose. Это позволяет runner
записать профиль и результаты в подготовленную upload-сессию.
Сервис `chem_conversions` не работает с файлами и остаётся независимым от сессии.
`read_data_file(file_name, session_id)` читает только bare-имя из
`/workdir/<session_id>/inputs/`. Инструменты `search_connected_datasets` и
`build_structure_research_report` принимают обязательный `session_id`, а пути
`sources[].file_path` задаются относительно `/workdir/<session_id>/`, например
`inputs/molecules.csv`. Абсолютные пути, `..`, выход через символьную ссылку и
идентификатор другой сессии отклоняются.

Для mapped source сохраняются поля `dataset_name`, `smiles_field`, `id_field` и
`name_field`. Пустой или неверный SMILES завершает чтение понятной ошибкой с
именем файла и номером строки; записи не пропускаются молча.

## Прямые проверки без модели

Unit-тесты обоих сервисов:

```bash
make test-chemistry
```

После запуска можно вызвать инструмент напрямую через вспомогательный MCP-клиент:

```bash
docker compose -f docker-compose.claude.yml --profile chemistry run --rm --no-deps chem \
  python smoke_http.py --url http://chem:5058/mcp \
  --tool read_data_file \
  --arguments '{"file_name":"molecules.csv","session_id":"chem-smoke"}'

docker compose -f docker-compose.claude.yml --profile chemistry run --rm --no-deps chem \
  python smoke_http.py --url http://chem:5058/mcp \
  --tool profile_molecule_physchem_and_adme_heuristic \
  --arguments '{"molecules":["CCO"]}'
```

Перед первым вызовом чтения положите пример в
`workdir/chem-smoke/inputs/molecules.csv`. Эти проверки не обращаются к LLM.
Конверсия через PubChem и ChemX требуют сети; NN-профиль дополнительно загружает
модель, поэтому для базовой проверки запуска они не нужны.

Удалённые расчёты в режимах GPU/Auto и передача файлов описаны в
[инструкции удалённого химического исполнителя](chemistry-remote.md).
