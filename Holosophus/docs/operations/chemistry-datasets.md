# Реестр и локальное хранение химических наборов

Источники задаются в [`chem_mcp/datasets.yaml`](../../chem_mcp/datasets.yaml).
YAML содержит десять существующих ChemX-наборов и их подготовленные описания.
SQL-клиент использует сохранённые версии таблиц. Общий MCP-каталог, описание,
SQL и прямой RDKit-поиск по серверным наборам подключены к химическому профилю.
Литературный агент, proposer и экспериментатор используют общий набор
инструментов; менеджер выбирает источники и передаёт их ID специалистам.
Схемы таблиц поступают через `describe_dataset`, а не встраиваются в промпты.

## Инструменты доступа

| MCP-имя без префикса `mcp__chem__` | Назначение |
|---|---|
| `list_datasets` | Краткий список ID, назначения и операций. Без загрузки таблиц. |
| `describe_dataset` | Сохранённые описание, схема, примеры и сведения о версии; без скачивания данных. SQL работает с таблицей `dataset`, дополнительный `row_idx` нумерует записи с нуля. |
| `query_dataset_sql` | Запрос к одному набору по `dataset_id`. Читает сохранённую версию или подготавливает отсутствующий набор. |
| `search_connected_datasets` | RDKit-поиск по одному/нескольким серверным наборам и файлам текущей сессии. |

Если согласования включены, каталог и сохранённое описание доступны до
согласования источников. SQL и структурный поиск требуют согласования
источников, но могут использоваться для подготовки плана. Расчёты и вызов
экспериментатора по-прежнему ждут согласования плана. При выключенных
согласованиях дополнительных ограничений нет; состав инструментов каждой
роли сохраняется. Общий профиль не получает химические MCP.

Старые `search_chemx_*` принимаются сервером для прямых вызовов прежних
клиентов, но не публикуются в `tools/list` и исключены из списков новых агентов.
Они выполняют запрос через тот же SQL-клиент и сохранённые таблицы; прежние
правила согласования для этих имён сохранены. Клиенты, обновляющие каталог,
должны использовать `query_dataset_sql`. Это совместимость MCP-вызова,
а не подтверждение модельного продолжения каждой старой беседы.
В CodeArkt этой рабочей копии химический MCP не подключён к `MCP_CONFIG`
и спискам ролей; его обычные инструменты и канонические промпты не менялись.

11 сентября 2026 года проверен рабочий Docker MCP до и после пересоздания
только `chem`: SQL прочитал 1 721 и 2 923 записи, точный RDKit-поиск нашёл
заданные структуры за пределами первых 100 строк, поиск бензольного кольца
обработал оба набора вместе с файлом сессии. Версии, SHA-256 и время изменения
сохранённых файлов совпали. Проверены ограничения SQL, сессионные пути,
состав инструментов ролей и вызов прежнего MCP-имени. Новый прогон с LLM
или полный химический эксперимент в эти проверки не входил.

Пример параметров структурного поиска:

```json
{
  "sources": [
    {"dataset_id": "benzimidazoles"},
    {"dataset_id": "oxazolidinones"},
    {"file_path": "inputs/molecules.csv", "smiles_field": "structure"}
  ],
  "session_id": "current-session-id",
  "query_smiles": "c1ccccc1",
  "match_type": "substructure",
  "max_results": 20
}
```

`session_id` подставляется hook текущего исследования, даже если агент передал
другой ID. Каталог, описание и SQL не получают сессионных параметров.
Серверный источник принимает
только `dataset_id`; его путь и mapping выбирает реестр. Путь файла остаётся
относительным к сессии; переходы в другие сессии и через внешние симлинки
отклоняются. `exact` сравнивает канонические SMILES, `substructure` использует
RDKit `HasSubstructMatch`.

Каждый читаемый источник проверяется целиком; `max_results` ограничивает
только возвращаемые совпадения. `matched_rows` — число совпадений среди
обработанных корректных записей, `returned_rows` — число выданных,
`truncated` — наличие невыданных совпадений. В `sources` приведены результаты
каждого источника, число пропущенных плохих SMILES и до пяти примеров ошибок.
`partial: true` означает ошибки источников или пропущенные записи. Полный
отказ источников возвращает `ok: false`, а не пустую успешную выборку.
Неправильный SMILES самого запроса отклоняется до чтения источников.

Результат серверного поиска содержит `dataset_id`, версию и `row_idx`,
совместимый с SQL. `compound_id` — дополнительный идентификатор исходной записи.
Для файлов выдаются относительный путь и номер строки. Обёртка
`build_structure_research_report` использует тот же выбор источников и явно
обозначает частичное покрытие.

SQL допускает только чтение таблицы `dataset`, включая агрегации и CTE.
Запись, подключение других БД, PRAGMA и загрузка расширений запрещены
авторизатором SQLite. `row_limit` — 1–1000, по умолчанию 100; для SQL задан
бюджет 10 секунд, проверяемый обработчиком прогресса SQLite. Ошибка требует
исправить/упростить запрос.
Инструмент читает не более `row_limit + 1` строк результата для определения
обрезания; Python не собирает весь SQL-результат перед ограничением выдачи.

SQL-ответ содержит `source` с ID, версией и полным числом входных записей,
а также `columns`, `rows`, `returned_rows`, `truncated`. `row_count` относится
только к данному SQL-запросу: известен при полной выдаче, иначе равен null.
`LIMIT` внутри SQL является частью запроса и не доказывает отсутствие других
подходящих записей во всём наборе. Старые `search_chemx_*` также передают
источник и признак обрезания, сохраняя прежнее поле `rows`.

## Подготовка выбранных наборов

Команды выполняются из `Holosophus/`. Нужен Docker с работающей интеграцией WSL:

```bash
make up-chemistry
make chemistry-prepare-datasets
```

Вторая команда подготавливает только наборы с `preload: true` — Benzimidazoles
и Oxazolidinones. Она не запускает исследование или LLM. Первый запрос к
другому зарегистрированному набору загружает и сохраняет его автоматически.
Запуск MCP сам по себе не загружает таблицы.

На хосте данные лежат в `data/chemistry/`, в контейнере — `/data/chemistry/`:

```text
datasets/<dataset_id>/
    current.json
    versions/<version>/
        records.jsonl
        metadata.json
huggingface/                       вспомогательный кеш загрузки
```

Данные исключены из Git. Mount находится вне слоя контейнера; удалять этот
каталог для перезапуска сервиса не требуется. Рабочая папка сессий по-прежнему
монтируется в `chem` только для чтения. Каталог наборов в сессии не копируется.

`records.jsonl` содержит строки с исходными именами колонок. `metadata.json`
хранит SHA-256 таблицы, источник, разрешённый commit Hugging Face, дату подготовки,
число записей, фактические типы и до трёх примеров. Индекс `row_idx` добавляет
SQL-интерфейс; он не подменяет `compound_id`, который может повторяться между
публикациями. Количество строк не является количеством уникальных молекул.

Публикация версии переключает `current.json` после успешной подготовки файлов.
Одновременные обращения к одному новому набору сериализуются файловой блокировкой.
При ошибке загрузки/проверки действующая версия остаётся доступной. Повреждение
локальной копии возвращает ошибку контрольной суммы, а не запускает скрытую
загрузку другой версии.

## Явное обновление

```bash
docker compose -f docker-compose.claude.yml --profile chemistry run --rm --no-deps chem python -m prepare_datasets benzimidazoles --refresh
```

Новый запрос к SQL-клиенту увидит опубликованную версию. Прежние версии
сохраняются. Изменение параметров источника в YAML требует явного `--refresh`:
старая копия не должна незаметно выдаваться за другой источник. Если нужна
заданная версия Hugging Face, добавьте `revision` с commit ID в `source`.

## Подключение своего набора

Для таблиц поддерживаются CSV, JSON-массив объектов (или объект с `records`)
и JSONL. Запись в реестре выглядит так:

```yaml
  local_example:
    title: Демонстрационные соединения
    description: Небольшая таблица соединений и измеренных значений в мг/л.
    source:
      type: file
      path: /data/chemistry/imports/example.csv
    preload: false
    operations: [sql, structure]
    smiles_field: smiles
    id_field: compound_id
    schema:
      - name: smiles
      - name: compound_id
      - name: value
    example_rows:
      - smiles: CCO
        compound_id: A
        value: 1.5
```

1. Поместите таблицу в каталог, доступный `chem`, например
   `data/chemistry/imports/example.csv` на хосте.
2. Добавьте запись в `datasets` внутри YAML: ID, назначение, источник, схему и
   mapping. Относительный `source.path` разрешается от каталога реестра.
   Название набора не используется как путь. `row_idx` зарезервирован SQL-клиентом.
3. Схему и примеры подготовьте из образца или документации источника. Неизвестный
   тип колонки можно не указывать; число строк считается при загрузке. Укажите
   смысл величин и единицы в `description`/`notes`. Пример не считается проверкой
   всей таблицы. `operations` описывает возможности источника; доступ агента
   дополнительно определяется опубликованными MCP-инструментами его роли.
4. Пересоберите образ после изменения встроенного YAML и подготовьте источник:
   `python -m prepare_datasets local_example` внутри химического контейнера.
5. Проверьте фактическую схему/сопоставления, число записей и небольшой запрос.
   Добавление источника в реестр само по себе не проверяет качество химических
   данных. Общие MCP-инструменты и Python-клиент принимают зарегистрированный
   ID; доступ конкретного агента зависит от его списка инструментов.

Для этой проверки вызовите `list_datasets`, `describe_dataset` с новым ID,
затем `query_dataset_sql` с `SELECT COUNT(*) AS n FROM dataset`. Для набора
с операцией `structure` дополнительно найдите известную молекулу через
`search_connected_datasets`, передав `sources: [{"dataset_id": "local_example"}]`
и `session_id` тестовой сессии. Эти MCP-запросы не требуют LLM.

Для Hugging Face вместо `type: file` задайте:

```yaml
    source:
      type: huggingface
      repo_id: ai-chem/Benzimidazoles
      config: default
      split: train
```

Добавление поддерживаемой таблицы не требует нового Python-инструмента. Для
другого формата или внешнего API потребуется отдельный загрузчик. Объявление
`structure` требует указать колонку SMILES; неподдерживаемые операции и
ошибки mapping отклоняются при чтении реестра.

## Настройки и проверка без Docker

- `CHEM_DATASETS_CONFIG` — другой YAML-реестр; по умолчанию поставляется вместе
  с кодом/пакетом. `--registry` переопределяет его в команде подготовки.
- `CHEM_DATA_DIR` — постоянный каталог версий; `--data-dir` переопределяет его.
  Без настройки используется `.cache/datasets` рядом с модулем.
- `HF_HOME` — кеш библиотеки загрузки. Глобальный offline-режим не нужен:
  подготовленные версии читаются напрямую, новые источники требуют сети.

Для операционной проверки без Docker в окружении с pandas, datasets и PyYAML:

```bash
PYTHONPATH=chem_mcp uv run python -m prepare_datasets --data-dir data/chemistry/datasets --preload
```

Команда не устанавливает эти зависимости автоматически. Реестр и описание
можно проверить без обращения к источникам через `DatasetRegistry` и
`DatasetStore.describe`. До загрузки возвращается `metadata_origin: registered`,
после — `snapshot`, фактическая схема и изменения относительно объявленной.

Типы SQL-значений сохраняются из таблицы; идентификаторы и SMILES в CSV читаются
как текст. Значения активности из JSON/Hugging Face вроде `5,52`, диапазонов
или неравенств не превращаются автоматически в числа. Для их интерпретации
нужны сведения о показателе и единицах.
