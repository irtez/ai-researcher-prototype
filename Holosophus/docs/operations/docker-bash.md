# Встроенный Bash Claude Code в Docker

`cc_runner.py` (веб-интерфейс) и `run_research.py` (CLI) направляют встроенный
инструмент Bash в отдельный контейнер исследовательской сессии. Механизм общий
для general и chemistry. Менеджер, локальный экспериментатор, writer и reviewer
сохраняют Bash; librarian, proposer и удалённый экспериментатор его не получают.
Удалённый экспериментатор продолжает использовать `remote_bash` через SSH.

Локальный `mcp__mle_kit__bash` исключён из CC-описаний и запрещён общим фильтром
и хуком. Сам инструмент MLE Kit сохранён для прежних клиентов. Другие MCP,
согласования и штатные фоновые задачи Claude Code продолжают использоваться.

Оба профиля загружают роли, MCP и callbacks из конфигурации приложения, с
`setting_sources=[]`: личные плагины и одноимённые проектные агенты не
подмешиваются в исследование. Настройки пользовательского CLI не меняются.
`ScheduleWakeup` исключён из инструментов исследования: он обслуживает
динамический `/loop`, а завершение фонового специалиста приходит штатным
уведомлением SDK.

## Подготовка и жизненный цикл

Runner требует доступ к Docker CLI и daemon до первого запроса к модели.
В `.env_example` выбран подготовленный образ `ai-researcher-executor:2026-10-10`.
Перед первым запуском соберите его из каталога `Holosophus`:

```bash
make executor-image
```

Образ расширяет прежний CUDA/ML-стек, сохраняя NumPy, pandas, PyTorch и остальные
вычислительные библиотеки. Добавлены Poppler (`pdfinfo`, `pdftotext`, `pdftoppm`),
curl, jq, file, шрифты DejaVu, RDKit 2025.9.6 и PyMuPDF 1.27.1. Zip/unzip,
fontconfig и сертификаты также включены явно. Базовый образ закреплён по
digest, Python-колёса — по версиям и SHA-256. Версии установленных системных
и Python-пакетов сохраняются в `/opt/holosophus/executor/`.

Для существующего `.env` задайте `CC_EXECUTOR_IMAGE=ai-researcher-executor:2026-10-10`
и перезапустите runner после завершения текущих исследований. Без переменной
сохраняется прежний резервный образ `phoenix120/holosophos_mle`. Пользовательский
образ можно выбрать той же переменной. Образ должен содержать Bash и Python 3.
Локальный подготовленный тег не опубликован в Docker Hub, его нужно собрать
на машине runner. Не меняйте тег прежнего базового образа для обновления.
`LOCAL_GPU_DEVICES` сохраняет прежний смысл: пусто — CPU, `all` или список
индексов — GPU при установленном NVIDIA Container Toolkit. Отказ Docker/GPU
возвращается как ошибка; исполнения команды на хосте в качестве замены нет.

Система создаёт контейнер `holo-cc-<hash пути сессии>`. Он работает во время
итерации, останавливается после завершения/отмены и запускается вновь при
доработке. Пакеты и файлы контейнера сохраняются. Другая сессия получает
отдельное окружение. Прежние установки в общем MLE-контейнере автоматически
не переносятся. Новое значение `CC_EXECUTOR_IMAGE` применяется только к новым
сессиям. Доработка существующей сессии использует её прежний контейнер и
установленные в нём пакеты. Смена GPU или служебного runtime-каталога
по-прежнему требует новой сессии.

Пауза использует существующий механизм `docker pause`, теперь для контейнера
одной сессии. Время штатного таймаута Bash продолжает идти во время паузы.
Контейнеры не удаляются автоматически: удаление потеряет установленные в их
слой зависимости. Просмотр принадлежащих этому механизму контейнеров:

```bash
docker ps -a --filter label=holosophus.cc.workspace
```

## Файлы, окружение и инструменты

- Каталог сессии смонтирован по тому же абсолютному пути, что на хосте.
  `/workdir/<session_id>` — контейнерная ссылка на него; `pwd -P` возвращает
  путь, доступный CLI. Поэтому смена каталога сохраняется между вызовами.
- Read/Write/Edit видят рабочие файлы напрямую. Запись этими встроенными
  инструментами ограничена папкой сессии, включая проверку ссылок наружу.
  Чтение инструкций writer на хосте сохраняется.
- Менеджер и все специалисты получают `SESSION_WORKSPACE` — точный абсолютный
  корень сессии. Read требует абсолютный `file_path`; относительные пути в
  поручениях отсчитываются от этого корня. В Bash они отсчитываются от текущего
  cwd, изначально совпадающего с корнем сессии. `mle/` — каталог артефактов,
  отдельной рабочей папки у экспериментатора нет. Файл, созданный скриптом в
  Docker, уже доступен native Read; переписывать его через Write не требуется.
- Это относится к общей папке сессии. Контейнерный `/tmp` не виден хостовому
  Read, поэтому изображения страниц PDF для просмотра сохраняются, например,
  в `.cache/pdf-pages/` внутри сессии. В обратную сторону служебные файлы SDK
  вне workspace читаются хостовым Read, при большом объёме — по частям.
- Общие изображения Paperbanana доступны в контейнере для чтения через
  прежнюю ссылку `figures/paperbanana`. Другие сессии туда не монтируются.
- Bash использует Python и PATH образа; `~/.local/bin` добавлен только внутри
  контейнера. Установка пакетов через Python/pip и виртуальные окружения
  возможна. Домашний каталог внутри контейнера — папка сессии.
- Сам CLI и native Read сохраняют хостовый PATH runner, включая PDF-утилиты.
  Пустые/относительные элементы и каталоги внутри workspace или runtime
  исключаются из этого PATH, чтобы агент не подменил хостовую утилиту.
  В Docker по-прежнему передаётся отдельный PATH образа и пакетов сессии.
- `llm_proxy_local` выбирает этот же контейнер, поэтому возвращаемый localhost
  остаётся доступен экспериментатору. В старом режиме выбирается прежний
  MLE-контейнер. Прокси останавливается вместе с контейнером; следующая
  доработка при необходимости вызывает инструмент снова.
- Служебные файлы префикса находятся в `.tmp/docker-executors/` вне доступных
  агенту каталогов. В контейнер передаётся отдельная временная папка для cwd
  и фонового вывода. Docker socket, конфигурация CLI и его авторизация не
  монтируются.

`CLAUDE_CODE_SHELL_PREFIX` задаётся только для SDK-процесса исследования.
Общие инструкции файлов, языка и исполнения находятся в
`holosophos/holosophos/prompts/shared/claude_code.yaml`. Блок файлов передаётся
каждой роли один раз; раздел исполнения добавляется только ролям с native Bash.
Хостовая обёртка передаёт исходную команду в Docker без исполнения её текста
на хосте. Контейнерный supervisor завершает группу процессов при закрытии
управляющего канала: так работают таймаут, TaskStop и отмена. Закрытие итерации
также останавливает весь контейнер. После аварии runner обёртки обнаруживают
смерть владельца и закрывают команды; следующий запуск очищает оставшиеся
процессы перезапуском контейнера.

Используйте штатный `run_in_background` для долгих задач. Произвольные
отсоединённые демоны не являются способом сохранить вычисление между
итерациями. Текущие HTTP MCP и SDK callbacks согласований не требуют shell;
добавление stdio MCP или shell hooks потребует учесть действие префикса.

## Проверки без модели

Сборка подготовленного образа проверяет расчёт RDKit, обработку PDF на русском
и английском, извлечение текста, растеризацию, график, изображение молекулы,
архивы и базовые вычисления. Через Bash агента тот же тест доступен командой:

```bash
python /opt/holosophus/executor/check_environment.py
```

Проверка не использует сеть и удаляет свои временные файлы.

Для проверки через штатную обёртку Bash без LLM, от UID пользователя runner:

```bash
RUN_DOCKER_TESTS=1 CC_EXECUTOR_IMAGE=ai-researcher-executor:2026-10-10 \
  uv run --no-sync python tests/executor_image_probe.py
```

Если явно задан `LOCAL_GPU_DEVICES`, этот сценарий также проверяет вычисление
PyTorch на CUDA. Проверочные контейнеры и файлы удаляются автоматически.

Описание расчётов для пользователя сохраняется как
[сводка экспериментатора](experiment-summaries.md). Ручной журнал фаз с
придуманным временем больше не требуется.

```bash
RUN_DOCKER_TESTS=1 uv run --locked --offline pytest --noconftest -q tests/test_docker_bash.py
RUN_DOCKER_TESTS=1 uv run --locked --offline python tests/docker_bash_cli_probe.py
```

Первая команда проверяет файлы, установку/сохранение пакета, отмену, закрытие
сессии и независимую паузу. Вторая запускает установленный CLI с фиктивным
ключом и локальными заранее заданными API-ответами: менеджер, субагент,
cwd, фон, timeout и TaskStop. Реальная LLM не вызывается. Проверочные
контейнеры удаляются отдельно от рабочих; вывод CLI остаётся в `/tmp`.

Это проверка локального пути исполнения. Из неё не следует изоляция
`remote_bash` на SSH-машине, проверка GPU или устойчивость ко всем способам
выхода из песочницы. Смоук через UI с настоящей моделью согласуется отдельно.

The `2026-10-10` executor tag also includes `column` from `bsdextrautils` for
formatting CLI tables. Build it with `make executor-image` and select it with
`CC_EXECUTOR_IMAGE=ai-researcher-executor:2026-10-10`. Existing research
containers retain their original image and installed packages.
