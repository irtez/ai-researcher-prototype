# Серверная история итераций Claude Code

Runner сохраняет отдельную запись для исходной задачи и каждого замечания
к готовому результату. Механизм общий для `general` и `chemistry`. Переподключение
SDK после лимита продолжает ту же запись и беседу. CLI использует те же записи
и снимки; журнал UI-событий заполняется только UI runner.

При новом запуске UI показывает подготовку сессии до первого события runner.
Чтение истории и метаданных начинается после этого подтверждения, когда сервер
уже создал запись. Сессия в очереди возвращает метаданные active=true даже до
создания беседы SDK; возможность доработки при этом выключена. Настоящие ошибки
чтения после принятия задачи отображаются обычным образом.

Ответ Agent о запуске фонового исполнителя не завершает его роль в UI:
связь с родительским вызовом сохраняется для сообщений и инструментов агента
до настоящего уведомления completed/failed/stopped. Для синхронного вызова
роль закрывает его итоговый ответ. Исторические события, ошибочно записанные
раньше этого исправления, автоматически не переатрибутируются.

Новые события Claude содержат дополнительный блок `activity` (version=1):
ID конкретного вызова агента и его родителя, поручение, ID вызова инструмента,
параметры, ответ, признак ошибки и время. Вызов инструмента и его ответ —
отдельные записи с одним callId. Подтверждение фонового запуска меняет состояние,
но не выдаётся за завершение. Известный автор сохраняется и для поздних сообщений
уже завершившегося агента. В UI-поток передаются те же sequence/iteration_id,
которые записаны на диск. Старые поля и журналы без activity остаются читаемыми.
Текст предпросмотра ограничен 64 000 символов с признаком truncated; двоичные
блоки изображений не копируются в ленту. Это не изменяет ответ, получаемый моделью.

## Хранение

### Идентификатор и название сессии

Новые сессии Claude Code получают технический ID `research_<UUID>` в UI,
API и CLI. Имя каталога не содержит задачу или модель. Старые ID и явно
указанные имена каталогов сохраняются; SDK UUID беседы остаётся отдельным
идентификатором для resume. CLI `--workdir` в обоих профилях должен указывать
на каталог непосредственно внутри общего `WORKSPACE_DIR`, доступного MCP.

В `.holosophus_ui/` отдельно хранятся `title`, `mode`, `created_at` и `model`.
UI ищет по названию и ID, читает тип/модель из метаданных; для старых папок
сохраняется прежнее чтение имени. Дата создания не меняется при переименовании.

При первом запуске UI/CLI оставляет начало задачи как запасное название
и запускает одну фоновую попытку через выбранную модель и подключение этой
сессии, включая её effort. Настройки описаны в [реестре моделей](model-connections.md).
Передаётся только начало исходной задачи (до 6000 символов), без файлов,
инструментов, MCP, исследовательской беседы и сохранения отдельной беседы.
Промпт `session_title.yaml` просит одну строку в 3–7 словах на языке задачи;
она проверяется на непустоту, одну строку и длину до 120 символов.

Основной запуск не ждёт названия. UI обновляет его без reload. При ошибке,
таймауте 45 секунд или завершении исследования до ответа остаётся запасное
название. Маркер `title_attempted` исключает повторную попытку при доработке,
resume и перезапуске runner. Изменённое вручную название не перезаписывается.
Смена названия не меняет ID, URL, планы, результаты или связи телеметрии.

### Общая папка MLE Kit

Native-инструменты Claude Code и MLE Kit используют одинаковый ID, включая
кириллицу старых сессий. MLE Kit проверяет ID как один компонент пути и больше
не заменяет символы имени. Редактор, исполнение, окружение и `sandbox.json`
опираются на этот каталог. Старые дубли с заменёнными символами не удаляются
и автоматически не объединяются с основной папкой.

Общий `MleSessionToolGate` подставляет ID в `bash`, `text_editor` и
`llm_proxy_local` в обоих профилях UI/CLI. Пути native внутри сессии переводятся
в относительные. Параметр `bash.cwd` допускает относительный каталог либо
абсолютный `/workdir/<ID>/...` внутри сессии; выход за её пределы отклоняется.

MLE Kit передаёт ненулевой код завершения команды как ошибку MCP (`isError=true`)
с кодом и сохранёнными stdout/stderr. Код 124 указывает на таймаут; 137 —
на принудительное завершение с возможным таймаутом, без предположения о точной
причине. Предупреждение в stderr при коде 0 остаётся успешным ответом. Ошибка
одного инструмента не останавливает весь агентский цикл: модель получает
сообщение и может исправить команду. Существующий UI выделяет признак ошибки.

### Вложения при доработке

В форме доработки завершённой сессии Claude Code можно прикрепить файлы тех же
форматов и размеров, что при новой задаче. Для отправки требуется текст
замечания. Функция общая для general и chemistry; во время активной итерации,
включая паузу, загрузка новых входов отклоняется.

Каждая партия имеет UUID. Сервер публикует файлы в `inputs/` под уникальными
именами `<stem>--<UUID>-<n>.<ext>`; flat-пути совместимы с химическими инструментами,
принимающими имя входного файла. Исходные имена, пути, размеры и SHA256 хранятся
в `.holosophus_ui/input_batches/<UUID>.json`. Совпадение исходного имени не
перезаписывает старый файл. В истории итерации показаны исходные имена и ссылки
на её версии входов; начальные вложения также видны в исходной задаче.

Повтор загрузки с тем же UUID и содержимым возвращает прежние пути. Другой
состав партии или изменённый файл отклоняется. После успешной загрузки форма
повторяет только запрос доработки; после потери ответа загрузки повторяется
та же партия. Авторизационный повтор сохраняет текст, файлы и обработку ошибок.
Изменение выбранных файлов создаёт новую партию. Смена страницы/полный reload
не сохраняет браузерные File-объекты; черновик загрузки на диске не запускает
исследование и не становится автоматически входом следующего сообщения.

Публикация использует ту же файловую блокировку, что выделение итерации,
с повторной проверкой активности после чтения запроса. Runner сверяет состав
и SHA256 партии, сохраняет `feedback_upload_id`, `input_files` и
`input_attachments` в настройках итерации, затем добавляет пути и исходные
имена к новому сообщению той же SDK-беседы. Партия относится только к одной
отправленной итерации. Старые документы не меняются загрузчиком; механизм
не является запретом произвольного редактирования файлов агентом через Bash.

Новые входы сбрасывают перенесённое согласование источников при начале
доработки. Менеджер описывает их в новом документе источников и запрашивает
решение, если галочка включена. При выключенной галочке разрешение также
удаляется, но вопрос не задаётся; старое решение не вернётся при последующем
включении. План согласуется по обычным правилам новой итерации. Техническое
переподключение той же итерации полученные решения не сбрасывает.

### История итераций

Каталоги и номера назначает сервер до запуска SDK. Метаданные находятся
в `.holosophus_ui/iterations/index.json`, файлы записи — в подкаталоге её ID:

- `events.jsonl` — события runner, включая отдельные `output`; каждое получает
  `iteration_id`, последовательный `sequence` и серверное время `received_at`.
- `answer.md` — последний полученный финальный текст SDK, если он есть.
- `result.md` — снимок результата успешно завершённой итерации.

Метаданные содержат номер, тип `initial|feedback|legacy`, исходное сообщение
пользователя, настройки, состояние, время, SDK ID, пути и контрольную сумму
снимка. Указатель `latest_result_iteration_id` изменяется только при сохранении
непустого результата успешной итерации. Ошибка, отмена, отсутствие успешного ответа последнего
SDK-хода или выход по лимиту не публикуют прежний документ как новый.

Запись происходит на стороне производителя событий и не зависит от чтения
HTTP-потока браузером. Метаданные заменяются атомарно после записи содержимого;
неподтверждённый хвост журнала отбрасывается при следующей записи. Завершённая
запись не перезаписывается поздним callback или отменой. Служебный каталог
исключён из обычных карточек артефактов.

При аварийной гибели процесса, когда финализатор не выполняется, запись может
остаться в последнем активном состоянии. После перезапуска runner его
`active=false` означает отсутствие задачи в этом процессе, а не доказанное
завершение сессии: CLI использует ту же историю. Автоматической сверки
владельца исполнения нет; UI может показывать прежнее «работает». Новая
пользовательская доработка закрывает такую запись с ошибкой и выделяет новую;
прежний успешный результат сохраняется. Это не полное аварийное восстановление:
несохранённые снимки планов погибшего запуска при таком закрытии не создаются.
Одновременный запуск UI и CLI в одной сессии не поддерживается.

## Документ результата и финальное сообщение

Для каждой итерации runner выделяет путь `results/0001/result.md` и создаёт
каталог. Менеджер получает этот точный путь новым сообщением в SDK-беседу;
для доработки также передаются предыдущий успешный снимок и исходный путь
для разрешения относительных ссылок. Постоянное имя `result.md` не требует
нумерации со стороны модели. Корневая копия нового документа не создаётся.

Общий контракт хранится в `claude_code.result_prompt` канонического
`holosophos/holosophos/prompts/system.yaml`. Пути, стадия исходная/доработка/
техническое продолжение и включённые согласования подаются в новом сообщении,
а не переписывают начало беседы. Описание доступного `request_approval`
стабильно при изменении выбранных этапов. При выключенных согласованиях
их инструкции и инструмент по-прежнему отсутствуют.

Менеджер создаёт полный UTF-8 Markdown-документ, затем кратко сообщает результат.
Обработка `ResultMessage` не записывает этот текст в документ. Совпадающее
терминальное представление последнего сообщения менеджера пропускается;
одинаковый текст другого хода или отдельный `ResultMessage` сохраняются.
CLI выводит полное сообщение, включая конец длинного ответа.

Stop-hook проверяет необходимые документы и согласования: если документ отсутствует, пуст, не читается
как UTF-8 или путь небезопасен, возвращает одно напоминание выполнить недостающий шаг.
Отсутствующее выбранное согласование также препятствует завершению.
Применяется ответ `decision: block` с причиной; интерфейс соответствует
[документации Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/hooks).
Счётчик принадлежит итерации и переживает техническое продолжение. Повторного
автоматического запроса нет; финальная проверка возвращает ошибку подготовки
результата. Операторские pause/stop/steer и обнаруженный лимит не расходуют
напоминание. После паузы или замечания успешность проверяется заново для
последнего SDK-хода.

Перед фиксацией повторно проверяются успешное завершение и текущий файл.
Прочитанные байты передаются хранилищу снимка вместе с исходным путём;
снимок не перечитывает уже изменившийся рабочий документ. Проверяется
подготовка файла, а не научная полнота результата. Для доработки также
требуется новый Markdown-план из `plans/<id>/`; выбранные согласования
проверяются перед фиксацией. [Правила и разрешённая подготовка](approvals-and-feedback.md).

## Чтение через API

`GET /ui/sessions/{session_id}/iterations` возвращает список метаданных,
`active_iteration_id` и `latest_result_iteration_id`.

`GET /ui/sessions/{session_id}/iterations/{iteration_id}?after=0&limit=200`
возвращает метаданные, `events`, `answer`, `result_content` и, для прежней записи,
`legacy_live_state`. `plans` содержит снимки планов даже ошибочных/отменённых
итераций; `approval_state` — состояния этапов и решения с текстами документов.
`after` — последний уже полученный `sequence`, граница
исключительная; `limit` — 1–1000 событий. `next_after` и `has_more` нужны для
следующей страницы. Обе ручки используют существующую проверку владельца сессии.

### Уведомление о завершении

`WS /ui/ws/sessions/{session_id}/iterations/{iteration_id}/completion` —
дополнительный канал UI ↔ API для обоих профилей. Клиент делает одну попытку
для активной итерации в течение жизни страницы; автоматического переподключения
нет. Выбор старой итерации в истории не меняет предмет подписки. Смена сессии,
выход из аккаунта или закрытие страницы закрывают соединение.

Первый кадр клиента — JSON с `client_id` и необязательным `token`. При включённой
авторизации API проверяет подписанный токен; без неё использует идентификатор
клиента, причём заголовок от nginx Basic Auth имеет приоритет. Токен не передаётся
в URL. Неполученная за 5 секунд или неверная подписка закрывается без данных.

API раз в секунду читает сохранённый статус, не забирая события из очереди runner
и не меняя историю. При `complete`, `error`, `cancelled` или `unknown` отправляет
один JSON `{"iteration_id":"0001","status":"complete"}` и закрывает соединение.
Если завершение произошло до подключения, уведомление отправляется сразу.
Отключение клиента прекращает ожидание. Команд управления через этот канал нет.

Получив уведомление, UI инвалидирует прежние HTTP-запросы истории и артефактов.
HTTP-опрос продолжается независимо от WebSocket, поэтому обрыв, отказ прокси или
ошибка канала не останавливают обновление и не становятся ошибкой исследования.
Основной POST/NDJSON-поток, согласования, загрузки и команды управления остаются
без изменений. Upgrade включён только для `/ui/ws/` в обеих конфигурациях nginx
и в Vite. Uvicorn использует явную зависимость `websockets`.

Проверка без LLM: `tests/test_iteration_completion_ws.py`,
`ui/tests/iteration-completion.test.ts` и
`ui/tests/iteration-completion-browser.py`. Последняя поднимает настоящий UI/API
с синтетической историей; `UI_TEST_URL=http://localhost:5062` проверяет рабочий
nginx. Перед таким запуском стек должен быть свободен: тест создаёт временные
сессии в `workdir`, блокирует все вызовы runner из браузера и удаляет свои файлы.

## История в UI

«Детали запуска» — основная вкладка: открывается после нового запуска и при
выборе существующей сессии. Здесь находятся результат, контекст итерации,
документы/согласования и сообщения агентов. Остальные вкладки показывают
материалы своих этапов без повторения большого блока задачи. Бывший «Обзор»
называется «Литература» и появляется по литературным материалам; исходный
запрос не считается литературным источником. Прямой адрес литературной вкладки
при отсутствии материалов показывает пустое состояние.

Над вкладками находится выбор «Исходная задача / Доработка N». По умолчанию
UI следует текущей или последней итерации; ручной выбор сохраняется для сессии
после обновления страницы. Кнопка «Текущая работа» возвращает автоматический
выбор. Просмотр истории не переключает исполнение и не меняет основу доработки.
Текущий запрос согласования остаётся над рабочей областью при любом выборе.

Результат читается из сохранённого снимка. Пока доработка выполняется либо
закончилась ошибкой/отменой, доступен явно подписанный последний успешный
результат. В блоке «Задача, планы и решения» находятся сообщение пользователя,
снимки планов, решения и финальный ответ менеджера. Основные документы —
«Источники» и «План этой итерации» со статусом согласования: файл и разрешение
больше не образуют две одинаковые карточки. Неизменённые одобренные источники
из прежней итерации явно подписаны; отозванное разрешение такой подписи не даёт.
История решений с их снимками находится в отдельном свёрнутом блоке.
Ручное/автоматическое согласование обозначается один раз. Если в папке плана
несколько документов, основным служит указанный в согласовании; остальные
снимки доступны в «Сохранённых документах планирования». При отсутствии
выбранного пути несколько файлов не выдаются за один окончательный план.
Ссылки документа разрешаются
относительно его исходного рабочего пути. Остальные вкладки и артефакты относятся
ко всей сессии; их содержимое не выдаётся за исторический снимок связанного файла.

Лента и панель ролей используют события выбранной итерации. Незадействованная
роль в законченной работе помечается «не выполнялся». Повторные и параллельные
вызовы учитываются до завершения всех вызовов роли. Верхний статус показывает
текущую работу независимо от выбранной записи истории.

Готовые текстовые блоки Claude Code показаны отдельными сообщениями с временем
получения; дельты с одним ID объединяются внутри сообщения. Серверная история
загружается постранично и дополняется по `sequence` без повторов. События каждого вызова доступны в его подвкладке; вкладки добавляются справа
в порядке старта и не переставляются при завершении. Менеджер содержит
карточки перехода к агентам и контекст итерации. Параметры и ответы инструментов
изначально свёрнуты, ошибки видны сразу. Прежняя раздельная лента заменена
этим представлением; записи без ID явно агрегируются по роли. Ограничение браузерного кеша
`live_state.json` не обрезает серверную историю, используемую этим представлением.

## Прежние сессии и восстановление

### Ожидание фоновых агентов Claude Code

Конец реплики менеджера (`ResultMessage`) не завершает итерацию, пока работают
его фоновые агенты. Runner продолжает читать ту же SDK-беседу до штатного
уведомления об их завершении и следующего ответа менеджера, без повторного
`query`, таймеров модели и расходования напоминания о файле результата.
Lifecycle hooks учитывают вызов раньше, чем его событие придёт в UI.
Пауза, остановка и замечание оператора работают и во время такого ожидания.
После разрыва соединения при лимите прежние незавершённые вызовы помечаются
прерванными; восстановленный менеджер проверяет артефакты и при необходимости
поручает работу снова. Контракт общий для CLI/UI и обоих профилей.

Проверки без LLM: `tests/test_background_wait.py`, `tests/test_run_pause_loop.py`,
`tests/test_ratelimit_resume.py`, `tests/test_result_contract.py`.

### Сохранённая история

Сессия без индекса показывается как одна запись `legacy`: имеющийся результат,
исходная постановка и сохранённая браузером лента. Утраченные итерации, время
и границы склеенных сообщений не восстанавливаются предположениями. GET ничего
не переносит на диск. Перед первой доработкой доступная прежняя запись
фиксируется; сервер сохранения UI-кеша делает это также до его сброса браузером,
учитывая серверный статус завершения, если браузерный статус устарел.

Предполагается один процесс runner, принимающий запуски. Его реестр отклоняет
одновременную доработку той же сессии; файловая блокировка сериализует запись
истории. После потери процесса следующая принятая итерация помечает оставшуюся
активную запись ошибкой и получает новый номер. При этом техническое
переподключение живого runner нового номера не создаёт. Отдельная координация
нескольких принимающих runner и защита архива от произвольного кода модели
в эту реализацию не входят.

CLI `--resume` используют только после остановки прежнего процесса этой
сессии. Одновременное выполнение CLI и UI в одном workdir не поддерживается
и не защищено общим реестром admission. Техническое продолжение незавершённой
итерации сохраняет её ID, путь, SDK-беседу и использованное напоминание;
выбранная политика фиксирована и сохраняется при последующих reconnect;
попытка изменить её через technical resume отклоняется.
Такое явное продолжение может открыть заново запись `error`/`cancelled`.
Успешную опубликованную итерацию оно не открывает: для исправления готового
результата нужна новая пользовательская доработка через UI. Без сохранённой
SDK-беседы `--resume` возвращает ошибку и не запускает новую беседу.

## Проверки

Локальные проверки хранилища, настоящих HTTP-ручек и runner с подставным SDK:

```bash
uv run --locked pytest --noconftest -q tests/test_iteration_approvals.py tests/test_result_contract.py tests/test_research_iterations.py tests/test_cc_runner_feedback.py holosophos/tests/test_ui_api.py
```

`--noconftest` исключает неиспользуемую этими тестами модельную фикстуру
из `holosophos/tests/conftest.py`. Вызовов LLM в этих сценариях нет.

UI: `cd ui && npm test && npm run build`. Браузерный сценарий запускается
из `Holosophus/` после сборки:

```bash
UI_TEST_PROFILE=general uv run --locked --with playwright python ui/tests/iteration-history-browser.py
UI_TEST_PROFILE=chemistry uv run --locked --with playwright python ui/tests/iteration-history-browser.py
```

Нужен установленный Chromium для Playwright; путь к существующему браузеру
можно задать через `UI_TEST_CHROMIUM`. Сценарий поднимает отдельный локальный API
на свободном порту и создаёт временную сессию, использует настоящие обработчики
истории, скачивания и UI. Метаданные runner и ожидающий вопрос синтетические;
модельного backend у этого сервера нет. Проверяются смена/перезагрузка истории,
план, сообщения, роли, новый результат, ошибка/отмена, ссылка на CSV и узкий экран.
Скриншоты сохраняются во временном каталоге, путь печатается при завершении.
