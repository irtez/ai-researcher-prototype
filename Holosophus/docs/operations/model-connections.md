# Подключение моделей и effort

Канонический реестр — `config/models.yaml`. Runner, CLI и UI API читают один
файл; в Docker он смонтирован в `/model-config/models.yaml`. Альтернативный
путь задаётся `AI_RESEARCHER_MODELS_CONFIG`. Перезапуск контейнеров после
редактирования реестра не требуется; UI получает обновлённый список при
следующей загрузке конфигурации.

## Запись реестра

`defaults` задаёт ID конфигурации по умолчанию отдельно для `claude_code`
и `codearkt`. Каждая запись `models` содержит:

- `label` — название в UI;
- `runtime` — `claude_code` или `codearkt`;
- `connection` — `subscription` для штатного входа Claude, либо `api`;
- `model_id` — идентификатор, принимаемый модельным сервисом;
- `base_url` и при необходимости `base_url_env` — адрес API;
- `auth.type` — `bearer`, `api_key` или `none`, `auth.token_env` — имя переменной
  с ключом. Значения ключей в YAML, браузере и истории не сохраняются;
- `generation.thinking` — для Claude Code: `adaptive`, `disabled` либо
  `enabled` с `budget_tokens`;
- `generation.max_output_tokens` — лимит вывода отдельного запроса;
- `generation.context_window` — размер контекста; в CodeArkt из него вычитается
  резерв для ответа;
- `generation.effort.choices` и `default` — допустимые уровни и начальный выбор.
  Задавайте только уровни, поддерживаемые моделью и её API. Если список
  отсутствует, переключатель effort скрыт и параметр не отправляется;
- `enabled: false` — пример или отключённая конфигурация, не предлагается в UI.

Поставляемые Opus/Sonnet/Haiku сохраняют прежние CLI-псевдонимы в `model_id`.
Чтобы закрепить версию, укажите полный поддерживаемый slug провайдера.
При внешнем API все внутренние модельные псевдонимы и модель подагентов
направляются на выбранный `model_id`. Самостоятельные вызовы менеджера,
подагентов и генератора названия используют одно подключение и выбранный effort.
Название запрашивается отдельно, без инструментов, с прежним коротким таймаутом.

Температура не входит в этот контракт: установленный Claude Agent SDK не
предоставляет такого параметра. При необходимости настройте её на сервере
модели. Неподдерживаемые поля в реестре вызывают ошибку, а не игнорируются.

## Claude Code

Для подписки оставьте `connection: subscription`; используется штатный вход
CLI. Для внешнего API включите пример `laboratory`, укажите идентификатор,
адрес сервиса с Anthropic Messages API и переменную авторизации. Для OpenRouter
адрес имеет вид `https://openrouter.ai/api`, для vLLM — адрес его Messages API
без суффикса `/chat/completions`. Наличие обычного OpenAI-совместимого endpoint
само по себе не подтверждает совместимость с Claude Code.

Значение ключа передайте окружению runner/CLI, например через существующий
`uv run --env-file .env ...`. Исследовательские настройки не записываются
в личный `~/.claude/settings.json`. В UI выберите конфигурацию и effort.
В CLI используйте `--model <ID конфигурации> --effort <уровень>`.

Конфигурация модели и effort сохраняются с сессией и используются при доработке
и техническом продолжении. Изменение `model_id` в общем реестре не подменяет
модель начатой сессии. Адрес, вид авторизации и имя переменной ключа перед
возобновлением сверяются с доверенным реестром; при несовпадении или отключении
конфигурации продолжение отклоняется. Восстановите прежнее подключение либо
начните новую сессию. Значение ключа читается из окружения заново.

Для внешних API MCP-инструменты передаются без отложенного поиска,
не требуя поддержки Anthropic `tool_reference`. Инструкции допускают прямой
вызов уже доступного инструмента. Поддержка tool calling и графических входов
зависит от выбранной модели и проверяется на конкретном подключении.

## DeepSeek: первая проверка официального API

Запись `deepseek-v4-pro` использует `https://api.deepseek.com/anthropic`.
Ключ указывается в `.env` как `DEEPSEEK_API_KEY=...`. После добавления или смены
ключа перезапустите host runner, чтобы он получил новое окружение. Сам реестр
перечитывается без пересборки UI; обновите страницу для появления модели.

В UI выберите `DeepSeek V4 Pro (0813)` и effort `low`, `high` или `max`.
Начальные параметры для малого сценария: `low`, включённое thinking,
`max_output_tokens: 16384`, `context_window: 200000`. Лимит вывода относится
к одному ответу API, а не к суммарному расходу исследования. `budget_tokens`
нужен формату настроек SDK, но DeepSeek его игнорирует; реальная интенсивность
рассуждения задаётся effort. `medium` у DeepSeek соответствует `high`, поэтому
отдельным выбором не предлагается. Температура в нашем CC-конфиге не задаётся.

По [текущей странице моделей](https://api-docs.deepseek.com/quick_start/pricing/)
на 15 сентября API-имя `deepseek-v4-pro` соответствует версии V4-Pro-0813.
В актуальном примечании DeepSeek сохраняет обслуживание Pro после 14 сентября;
прежнее сообщение об автоматическом переводе на Flash в поисковом кеше устарело.
Этот API-идентификатор не гарантирует неизменность версии в будущем.
[Совместимость Anthropic API](https://api-docs.deepseek.com/guides/anthropic_api/),
[thinking и effort](https://api-docs.deepseek.com/guides/thinking_mode/).
15 сентября выполнен первый настоящий UI-смоук: General/Local/low, делегирование
экспериментатору, Python-расчёт суммы и среднего пяти чисел, сохранение русского
результата. Запуск завершился за 32 секунды без ошибок инструментов; CLI-журналы
менеджера и экспериментатора содержат `model: deepseek-v4-pro`. Доработка,
химические инструменты и другие effort на этой модели ещё не проверялись.

## CodeArkt

Используйте `runtime: codearkt`, `connection: api`, OpenAI-совместимый адрес
и модель сервиса. Начальная запись читает `MODEL_NAME`, `BASE_URL` и
`OPENROUTER_API_KEY`, сохраняя прежнюю конфигурацию. Имя переменной ключа
не ограничивает сервис OpenRouter. Для другого провайдера добавьте собственную
запись и укажите её ID в `defaults.codearkt` либо выберите её в UI.

Запросы одного запуска используют выбранное подключение без изменения общего
объекта LLM других сессий. Для `effort` передаётся `reasoning_effort`;
при отсутствии поддержки не задавайте его список. Поле `thinking` для этой
среды отклоняется. Сохранённые публичные метаданные включают название и effort.
Существующие CLI/eval-вызовы с прямым именем модели вне UI сохраняются.

## Проверка

`PYTHONPATH=holosophos uv run --locked python -m holosophos.model_catalog`
проверяет структуру без API-ключей и сетевых запросов. Проверка включена в
`make verify`. `tests/model_catalog_cli_probe.py` проверяет установленный CLI
через локальный сервер с заранее заданными ответами: делегирование, чтение,
название, авторизация и параметры. Она не проверяет качество реальной модели.
Для конкретного провайдера нужен отдельно согласованный небольшой запуск.

Модели внутри самостоятельных MCP-сервисов и прокси для исследовательских
программ имеют собственные настройки; выбор основной агентной модели не
заменяет их конфигурацию.
