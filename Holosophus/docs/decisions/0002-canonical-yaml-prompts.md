# 0002. Canonical YAML prompts with `canon` / `codearkt` / `claude_code` schema

- **Status**: Accepted
- **Date**: 2026-04-22
- **Deciders**: project lead

## Context

Each specialist agent (`librarian`, `proposer`, `mle-solver`, `mle-solver-remote`,
`writer`, `reviewer`) and the top-level manager need a system prompt. Both
orchestrators need it (see ADR 0001), but in different shapes:

- **CodeArkt** consumes a system prompt assembled from role + guidelines +
  CodeAct framework boilerplate + worked examples + tool docs, fed into the
  CodeArkt runtime via `PromptStorage`.
- **Claude Code** consumes a `.claude/agents/<agent>.md` file with YAML
  frontmatter (`name`, `description`, `model`, `maxTurns`, `tools`,
  `mcpServers`) and a markdown body, picked up by the Claude Agent SDK
  at session start.

Earlier we maintained these two formats by hand. That produced silent drift
multiple times — guidelines changed in one place but not the other, the wrong
tool allowlist shipped to one orchestrator, eval scores diverged for reasons
unrelated to the LLM being benchmarked. The fix needed to be a single source
of truth that both paths could derive from.

## Decision

Specialist and manager prompts live as **canonical YAML files** in
`holosophos/holosophos/prompts/<agent>.yaml`, with three top-level sections:

- `canon.{description, role, guidelines, output_format}` — shared content,
  used by both orchestrators verbatim.
- `codearkt.{system_extras, examples, team_template, plan_extras}` —
  CodeArkt-specific: CodeAct framework wrapping, worked `<execute>` examples,
  tool docs in CodeArkt-flavoured form, plan-agent extras.
- `claude_code.{description, model, maxTurns, effort, mcpServers, tools,
  disallowedTools, prompt_extras}` — Claude Code-specific: frontmatter
  metadata + a `prompt_extras` body fragment with `mcp__`-prefixed tool
  references and Claude-Code-flavoured tool docs.

Loading paths:

- **CodeArkt**: `PromptStorage.compose(<agent>.yaml, codearkt_framework.yaml)`
  in `holosophos/holosophos/main_agent.py` assembles the system prompt at
  agent-factory time from `canon` + `codearkt` + the shared CodeAct framework
  boilerplate (`prompts/codearkt_framework.yaml`).
- **Claude Code**: `scripts/sync_claude_agents.py` reads `canon.*` +
  `claude_code.*` and writes `.claude/agents/<agent>.md` with an
  autogenerated banner. The Claude Code entry points
  (`scripts/run_research.py`, `scripts/run_eval_claude_code.py`) call
  `ensure_synced()` at startup, so the .md files are kept fresh on every
  invocation. The runner injects MCP server config and per-agent defaults.

`.claude/agents/` is **gitignored** — the .md files are pure build output
of the YAML. There is no drift gate because there is no manual sync step
to forget.

## Consequences

- Single place to change a guideline that should apply to both paths.
- The split is mechanical, not semantic — adding a rule to `canon` ships to
  both orchestrators automatically.
- New contributors edit YAML; the entry points regenerate `.claude/agents/*.md`
  at runtime, so there is no manual sync step.
- `.claude/agents/*.md` carry an autogenerated banner; the directory is
  gitignored. Manual edits are silently lost on next run. We accept this in
  exchange for orchestrator parity.
- Adding a new orchestrator in the future is a matter of adding a fourth
  top-level section and a writer for it; the canon stays untouched.
